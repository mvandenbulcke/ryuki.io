GET/api/audit/compliance/findings/{id}

read tier

GET /api/audit/compliance/findings/{id} — read ONE compliance finding (the read-by-id companion to the list + resolve/waive mutations, so an operator can inspect a finding before resolving/waiving it).

GET /api/audit/compliance/findings/{id} — read ONE compliance finding (the read-by-id companion to the list + resolve/waive mutations, so an operator can inspect a finding before resolving/waiving it). Audit-tier (via the /api/audit route prefix). Findings have no own site column, so an out-of-scope finding is scoped on its parent report's site and reported identically to a missing one (the 404 body) — no existence oracle, mirroring compliance_finding_resolve.

Example request

curl -s -H "Authorization: Bearer <token>" https://<your-host>/api/audit/compliance/findings/{id}

GET/api/audit/export

read tier

GET /api/audit/export — export the audit trail for SIEM ingestion.

GET /api/audit/export — export the audit trail for SIEM ingestion. Audit-tier. Cursor-paginated by the monotonic row id (after_id → next_after_id), with an optional [since, until] time window. Detail is redacted; each entry carries its hash-chain entry_hash so the SIEM can correlate with the verify endpoint. In dry-run / no-DB mode there is no durable chain, so this returns an empty export. The cursor yields no duplicates; for guaranteed completeness (no gaps under concurrency) periodically re-export a CLOSED time window — see audit::export_audit. Use the cursor with a stable window, or id-only.

Query parameters

NameTypeRequiredDescription
sinceStringoptionalInclusive lower time bound (RFC3339).
untilStringoptionalInclusive upper time bound (RFC3339).
after_idi64optionalCursor: return rows with id strictly greater than this (default 0).
limiti64optionalMax rows per page (default 500, capped 5000).

Example request

curl -s -H "Authorization: Bearer <token>" https://<your-host>/api/audit/export

POST/api/audit/log/verify

audit tier

POST /api/audit/log/verify — re-verify the audit-log hash chain and report whether history is intact (and the first divergent row id if not).

POST /api/audit/log/verify — re-verify the audit-log hash chain and report whether history is intact (and the first divergent row id if not). Audit-tier gated. In dry-run / no-DB mode the chain does not exist, so this is a no-op that reports verified with a non-durable note.

Example request

GET/api/audit/retention

read tier

GET /api/audit/retention?retention_days=N — audit-log retention/growth report (#62).

GET /api/audit/retention?retention_days=N — audit-log retention/growth report (#62). The append-only, hash-chained trail only grows; this surfaces how many entries have aged past a retention window (default 365d, bounded) and whether archival/partitioning is due — the read input to that SEPARATE, hash-chain- preserving step. Audit-tier; empty + durable:false with no DB.
